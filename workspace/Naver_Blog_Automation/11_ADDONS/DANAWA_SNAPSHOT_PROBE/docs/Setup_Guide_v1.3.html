2. 이번 주 목표

실제 제품 한 개의 저장 HTML에 구매 가능한 개별 가격 후보가 구조화 데이터로 존재하는지 확인합니다. 저장 HTML에서 schema.org/Product와 Offer JSON-LD만 찾습니다. AggregateOffer.lowPrice는 조건이 특정되지 않은 최저가 요약일 수 있어 개별 상품 후보로 채택하지 않습니다.

데이터를 찾지 못한 결과도 중요한 성공 결과입니다. 추측값을 만들지 않고 NO_STRUCTURED_OFFERS로 보고하면, 다음 단계에서 사이트별 API·승인 피드·수동 CSV 중 적합한 접근을 선택할 수 있습니다.

이번 주 성공 산출물

snapshot_report.json에 JSON-LD 발견 여부·모델·옵션·후보 가격·보류 이유·원본 해시(SHA-256)를 저장합니다. snapshot_report.html로 사람이 확인합니다. 모든 필수 검토 항목을 통과한 경우에 한해 candidates_for_review.csv에 후보 행이 생성됩니다. 이 CSV도 게시 전 추가 검토용입니다.

4. 실제 상품 HTML 1개로 테스트하기

  1. 사용이 허용된 범위에서 다나와의 특정 제품 페이지를 브라우저로 확인하고 HTML 페이지 저장본을 준비합니다. 확장자가 .html이어야 합니다. 저장 기능이 비동기 데이터까지 보존하는지는 보장되지 않습니다.
  2. fixtures/manual_meta_template.json을 복사해 source_page, 모델 번호, 옵션, 실제 확인시각(+09:00 포함)을 입력합니다.
  3. 사용 범위가 확인되지 않으면 usage_permission: "unknown"을 유지합니다. 배송비와 결제 조건을 확인하지 못했다면 null, unknown으로 둡니다. 모르는 값에 0을 넣지 않습니다.
  4. run_snapshot.bat 실행 후 HTML 저장 경로와 메타 JSON 경로를 입력합니다. output/manual/snapshot_report.html을 확인합니다.
  5. 보고서에서 후보 수와 보류 사유를 확인하고, 승인된 데이터 이용 범위에서만 추가 검증에 사용합니다. HTML의 원본 해시를 다른 검증 기록과 함께 보관합니다.

메타데이터 작성 예시

{
  "target": {"query": "정확한 상품명", "model": "모델번호", "variant": "옵션"},
  "source_page": "https://prod.danawa.com/info/?pcode=제품ID",
  "observed_at": "2026-11-01T08:00:00+09:00",
  "usage_permission": "unknown",
  "shipping_fee": null,
  "payment_condition": "unknown"
}
오해하기 쉬운 점: usage_permission="confirmed"를 직접 입력해도 법적 이용 허가가 자동 부여되는 것은 아닙니다. 또한 HTML 저장시각이 사이트가 보증한 가격 시각은 아닙니다. 이 파일만으로 전체 사이트 최저가를 증명할 수 없습니다.

8. 한 가지 핵심 Blocker

허용된 범위에서 반복적으로 제공받을 수 있는 ‘동일상품·옵션·배송비가 명시된 가격 근거’를 확보할 수 있는가? HTML 저장본이 가격을 포함하지 않거나 재사용 권한이 없다면 자동 스크래핑으로 넘어갈 수 없습니다.

다나와 이용약관은 회사 지식재산권 정보의 무단 영리 이용을 제한합니다. 데이터 성격·이용 범위·제공 주체를 먼저 확인해야 합니다. 확인 전에는 브라우저 우회·대량 수집 기능을 넣지 않습니다.

기술적으로도 페이지 화면에 가격이 보인다는 사실만으로 저장 HTML의 JSON-LD에 개별 판매 조건이 포함되어 있다는 보장은 없습니다. NO_STRUCTURED_OFFERS가 나오면 무리하게 숫자 정규식을 확대하지 말고 공식 피드·판매자 제공 데이터·기존 수동 CSV 경로를 검토합니다.

9. 다음 단계 진행 조건

이번 보고서로 실제 HTML과 메타값을 확보했다면, 이어서 허용된 데이터 공급 경로의 입력 Adapter 1개만 구현합니다. 그 Adapter가 v1.1 검증 엔진과 v1.2 CSV Bridge에 연결되어, 실제 상품 1개 × 후보 3개에서 오류 없이 통과하는지를 검사합니다.

이후 네이버쇼핑은 별도 승인된 가격 소스를 찾아 같은 PriceCandidate 계약으로 연결하고, 마지막에는 기존 이미지 원본 보존/354×472 리사이즈와 7열 표를 재검증합니다. 어느 단계도 네이버쇼핑 종료 API를 사용하지 않습니다.
