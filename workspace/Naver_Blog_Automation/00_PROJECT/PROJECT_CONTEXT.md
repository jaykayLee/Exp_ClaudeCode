## 1. 목적과 고정 요구
Windows Python 기반으로 다나와 최저가 → 네이버쇼핑 최저가 → 상품 이미지 다운로드/증명사진형 규격화 → 정확한 7열 표 → 네이버 블로그 적용으로 연결한다.
최종 목적은 일일 블로그 운영 보조/자동화이지만 이번 기준은 설치·자료 처리·검토 기반이다. 이미 전체 자동화가 완성됐다고 가정하지 않는다.

필수 열은 순서와 제목을 바꾸지 않는다.
`No. | 상품명 | 이미지 | 다나와 최저가 | 사이트 주소 | 네이버 최저가 | 사이트 주소`
두 사이트 URL은 내부 키 danawa_url/naver_url로 분리한다.

사용자는 프로그램을 BAT 더블클릭으로 설치하고 일상 실행은 start_panel.bat 하나로 수행하길 원한다. HTML 안내에서 처음 설치부터 실제 적용 순서를 따라갈 수 있어야 한다. 공통 코어와 수집·발행 어댑터를 분리해 Google Blogger, WordPress 등으로 확장한다.

## 3. 실제 산출물과 상태
구현: Windows 설치/실행/진단/테스트 스크립트, 로컬 HTML 안내/패널, 상품 팝업, 수동 가격 입력/JSON, 원본 보존, EXIF/투명도/비율 유지 이미지 변환, 정확한 7열 HTML, 누락·가격 유효기간·확인시각 검토, 동시 실행 잠금, 콘텐츠 브리프 템플릿 생성/MD 저장, 네이버 수동 전달 가이드.

이미지 HTTPS 다운로드는 기본 비활성화한다. 사용 권한 선언, 정확한 호스트 allowlist, 공인 IP, TLS 호스트 검증, 리디렉션 재검사, 최대 크기/픽셀 제한을 적용한다. 구현과 모의 응답 검증만 있으며 실제 호스트 검증은 별도이다.

미구현/미연결: Danawa live, Naver Shopping live, 네이버 원격 초안/사진 업로드/발행, Blogger/WordPress API. 발행 클래스 publish()는 명시적 미구현 오류를 반환한다. 기존 이름이나 버튼이 있다는 이유로 구현 완료로 판단하지 않는다.

선택 일일 작업은 사용자 확인 후 Windows 작업 스케줄러에 등록하는 로컬 자료 검토이다. 가격 갱신·사이트 수집·로그인·게시가 아니다. 설치만으로 예약을 등록하지 않는다.

## 4. 구조
- 00_PROJECT: CONTEXT, MANIFEST, LOCK, REGISTRY, CHANGELOG, ROADMAP, QA.
- 01_CONFIG: 예제/사용자 설정, 입력 스키마.
- 02_CORE: 검증·이미지·표·파이프라인. Step4 exporter 인터페이스 유지.
- 03_PROVIDERS: PriceProvider / PriceCandidate / 승인 입력 / 사이트별 연결 지점.
- 04_CONTENT: 출처 메타데이터, 새 글 템플릿, 사용자 브리프.
- 05_PUBLISHERS: prepare/publish 분리, 플랫폼별 연결 지점.
- 06_UI: 자기완결형 한국어 HTML 가이드·입력·데모·브리프 생성.
- 07_DATA: inbox(운영 입력), samples(가상 테스트), images/original·resized, state.
- 08_OUTPUT/runs: 실행별 HTML, images/, normalized_products.json, run_report.json, NAVER_HANDOFF.md.
- 09_LOGS: 사용자 PC 설치·진단·테스트 기록.
- 10_TESTS: 오프라인/로컬 HTTP 테스트.
- 11_ADDONS: 독립 모듈 계약·등록 예제. 자동 설치/탐색 로더는 아직 없음.
- 12_BACKUP/legacy: 이전 ZIP 원본.
- tools: bootstrap/server/run_once/doctor/qa_runner/schedule와 내부 의존성 lock.

PMA 형식은 이 프로젝트 안의 파일·버전 계약으로 구성한 것이다. ChatGPT의 프로젝트 UI나 외부 저장소를 자동 생성/이동했다고 말하지 않는다.

## 5. 설치·실행 계약
권장: Windows 11 x64, Edge/Chrome. Python >=3.11,<3.14 x64 탐지, 없으면 사용자 동의 후 3.13 계열 설치. 최신 전체 Python 버전이라는 의미가 아니다.
WinGet exact Python.Python.3.13 per-user → 실패 시 python.org 3.13.16 서명 확인 대체 설치. 서명 오류 또는 회사 정책 차단은 중단하고 로그 확인.
Pillow==12.3.0을 .venv에 설치한다. 사용자가 requirements.txt를 직접 설치하도록 하지 않는다.

`install.bat → start_panel.bat → 데모 3개 → Python 검증·표 생성`
진단 doctor.bat, 회귀 검사 smoke.bat. 내부 문서만 볼 때 open_guide.bat.
일일 예약 enable_daily_review.bat, 해제 disable_daily_review.bat. PC 켜짐·로그인 상태 필요. 실제 PC 시간대 기준. 비밀번호 저장/자동 깨우기 없음.

## 6. 데이터와 안전 규칙
가격은 양의 단일 금액 또는 None이다. 범위·월납입금·서로 다른 가격 문자열의 숫자를 합쳐 저장하지 않는다.
모델·옵션·같은 상품인지·배송비/카드/쿠폰 조건·원본 URL·실제 확인시각을 분리한다. 동일상품 체크는 사용자 선언이며 자동 검증이 아니다.
일부 수집 실패에도 상품 행을 버리지 않으며 미수집을 0원으로 표시하지 않는다.
기본 가격 검토 유효기간은 24시간. 재출력해도 실제 확인시각을 변경하지 않는다.
DEMO_ONLY는 가상 자료, HOLD는 검토 보류, READY_FOR_MANUAL_REVIEW는 형식 검사만 통과한 사람 검토 대상이다. 어느 상태도 자동 발행을 허가하지 않는다.

이미지는 약 3x4cm에 대응하도록 선택한 354x472px/300dpi 기본값을 사용한다. 공식 네이버/정부 제출 규격이라고 주장하지 않는다. 흰 여백·중앙 배치로 비율을 유지하고 원본을 보존한다.
이미지 사용 권한을 출처 표기만으로 대체하지 않는다. 직접 제작·사용 범위를 확인한 라이선스·명시적 허락 자료만 처리한다.
127.0.0.1에만 바인딩, Host/Origin·요청 토큰 검사, 임의 디렉토리 서빙 없음. 비밀번호/키/세션을 HTML에 저장하지 않는다.

## 7. 다른 블로거 참고와 새 콘텐츠
참고 자료: ProBlogger의 독자 문제 해결·편집, Smart Passive Income의 독자 적합성과 정직한 설명, Google Search Central의 직접 근거·비교·장단점 지침. 이들을 현재 네이버 공식 파워블로거나 수익/순위 검증 목록으로 표현하지 않는다.

흐름: 참고 URL/작성자/확인일 → 사실·의견 구분 → 공식 정보로 재검증 → 내 관찰/측정/선택 이유 → 새로운 독자 질문과 목차 → 출처·이미지 권한·이해관계 → 사람 검토.
타인의 글 전문/사진을 자동 수집하거나 단어만 바꿔 게시하지 않는다. 직접 써보지 않은 제품에 사용 경험을 만들어내지 않는다. 표가 갱신됐다는 이유로 저부가가치 글을 매일 반복 게시하지 않는다.

샘플 제목: “표시 최저가보다 먼저 확인할 세 가지: 모델·배송비·확인시각”. 실제 가격·측정 없는 설계 예시이다.
콘텐츠 브리프는 사용자가 입력한 근거를 템플릿으로 조합하며 외부 AI 호출/자동 사실검증/완성 글 게시 기능이 아니다.
출처 레지스트리: 04_CONTENT/references/source_registry.json.

## 8. 검증과 정직한 표기
- Python 3.13.5/Linux: 오프라인·로컬 HTTP 테스트 31개.
- 이전 v0.4 원본 자체 테스트 2개와 ZIP CRC 통과.
- Chromium/Playwright: UI 검사 15개, JS 오류 없음. 데스크톱/모바일 렌더링.
- 브라우저의 직접 URL 탐색은 컨테이너 정책상 제한돼 set_content 렌더링과 실제 로컬 서버 테스트 브리지를 사용. Windows 브라우저 URL 실행을 검증했다는 의미가 아니다.
- BAT CRLF/인코딩·구조와 ZIP 재해제는 별도 정적/패키지 검사. Windows 설치·예약·원격 수집·네이버 게시 미검증.

상세 결과: 00_PROJECT/QA. 사용자 Windows에서 실행한 최신 결과는 09_LOGS가 기준이다.

## 9. 다음 실행 지침
주간 안내는 이 기준과 실제 로그를 먼저 확인한다. 새 주차라는 이유만으로 다음 단계가 완료됐다고 전제하지 않는다.
1. Windows 설치/데모/테스트 결과가 없으면 먼저 이 단계를 검증한다.
2. 다나와: 정확한 모델 3개에 대해 허용된 접근/제공 경로·데이터 이용 조건 확정 후 live를 구현·3회 반복 검증한다.
3. 네이버쇼핑: 종료 API 제외, 대체 허용 경로를 확정한다. 없으면 수동 입력을 유지한다.
4. 같은 모델 가격·이미지·7열 표를 통합한 뒤 일일 실행을 검증한다.
5. 그 이후 네이버 게시 준비/초안 연계 수단을 검증하고, Blogger/WordPress는 별도 발행 어댑터로 확장한다.

이번 주 작은 목표: 내 PC에서 데모 3개와 실제 상품 1개의 검토 자료 생성.
주요 blocker: 자동 가격 수집에 쓸 허용되고 안정적인 데이터 경로.
